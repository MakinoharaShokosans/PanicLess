# 后端真实数据与操作接入报告

日期：2026-11-13。范围：后端代码、配置及验证；没有修改前端。

本轮补齐终端执行、任务暂停、文件回滚、主机遥测和操作设置的实际后端链路。前端当前的定时器、预设列表、默认报告和虚假成功提示仍需前端 Session 替换，不能因为后端接口已提供就认为页面已经接通。

## 17 项对应关系

所有业务路径以下均省略 `/api/v1` 前缀，沿用现有鉴权与统一错误响应。

## 新增接口用法

更新后需要重启后端和由其托管的 bash_shell sidecar，使新增请求字段与路由同时生效。项目根目录启动命令：

```bash
PYTHONPATH=backend/src backend/.venv/bin/python -m agent_runtime.cli --config config/config.toml start --no-frontend
```

下述 HTTP 示例沿用应用现有登录/令牌接入方式，未展示真实凭据。

### 非交互终端与暂停

```http
POST /api/v1/sessions/{session_id}/terminal/execute
Content-Type: application/json

{"command":"df -h","timeout_sec":10}
```

返回 `command_id`、`session_id`、`workspace_id`、`mode: non_interactive` 和 `result`。`result` 复用工具结果，含真实正文、退出码、耗时、截断及超时信息。命令执行失败或策略拒绝也可能通过 HTTP 200 返回，必须检查 `result.ok`，不能只看 HTTP 状态。

默认权限沿用工作区/后端配置。请求可提供 `permission_level`；`full_permissions` 必须提供 `confirm_full_permissions: true`，且依然经过原有命令审计与 sidecar 校验。并发冲突返回 409，未装配执行服务返回 503。复用现有认证，不绕过原有权限链。

```http
POST /api/v1/tasks/{task_id}/control
Content-Type: application/json

{"action":"pause"}
```

返回 202。`GET /api/v1/tasks/{task_id}/control` 返回实际 `control_state`：`autonomous`、`pause_requested`、`paused`、`inactive`。当前模型调用或工具批次完成后才停在下一步边界。恢复使用同一路径 `{"action":"resume"}`，不使用原有用于中断续跑的 `/resume` 来解除此暂停。

终端、回滚和 Agent 共用会话人工操作互斥。只有 Agent 真正暂停或结束后才可执行人工操作，人工操作结束前不可恢复 Agent。暂停不杀死在执行的命令；重启后按原有中断恢复流程处理。

当前限制：没有 PTY、stdin 或实时输出流。手工命令长输出的完整产物在实际 `artifact_path`，尚没有对应的 HTTP 下载入口；它不属于普通 TaskRecord，不能用任务产物接口伪造下载链接。

### 文件备份与回滚

`write_file`/`edit_file` 修改既有文件前生成独立 UUID 备份，存于应用数据目录 `backups/{task_id}/{backup_id}/`。每份保留原文件、路径、权限、时间、前后哈希；连续编辑不会覆盖上次备份。

工具结果与 `tool.result` 事件的 `backup` 字段包含 `backup_id`、`path`、`backup_path`、`created_at`、`before_hash`、`after_hash`、`mode`。

- `GET /api/v1/tasks/{task_id}/backups`：列出实际备份。
- `POST /api/v1/tasks/{task_id}/backups/{backup_id}/restore`：无请求正文，恢复文件，返回 `restored` 或 `already_restored`。
- 缺失为 404；后续文件修改或备份损坏为 409；权限不足为 403。不会覆盖已发生的其他修改。

新建文件没有原文件备份，不能假装可恢复；历史无元数据备份不猜测目标，也不自动迁移。

### 工具参数与机房规则

`GET /api/v1/settings/tools` 返回有效值。`PUT` 提交完整的两项配置：

```json
{"bash_max_timeout_sec":120,"bash_output_max_bytes":4096}
```

最大超时必须在 1 到配置文件 `bash_shell.max_timeout_sec` 之间；输出字节预算为 256 到 1048576。配置文件默认分别为 600 秒、8192 字节。实际默认命令超时仍取 `bash_shell.timeout_sec`（60 秒）并受界面设置的最大值限制。工具显式将超时和输出预算传给 sidecar，stdout/stderr 正文共享预算，完整输出仍持续落盘。

覆盖值写入已有 SQLite `app_settings`，重启保留；不改写 config.toml。下一次任务/续跑装配及下一次人工命令生效，在途工具保持快照。

`GET/PUT /api/v1/settings/rules` 使用 `{"content":"机房规则正文"}`。默认空字符串表示用户未配置规则；最多 20000 字符，空白清除。保存到 SQLite 后追加到主 Agent 和子 Agent 系统提示词，下次装配生效；不替换原系统提示词。

### 主机遥测与诊断

`GET /api/v1/system/telemetry` 读取 Linux `/proc`、挂载信息和 `statvfs`，用相邻采样计数差计算 CPU/磁盘速率。返回时间戳、采样时长及各部分状态，主要字段：`host`、`load_average`、`cpu_used_percent`、`io_pressure`、`network`、`disks`。

范围是后端进程可见的主机/容器命名空间。网络列表有返回上限，并提供总数及 `truncated`；进程权限不足、块设备不可映射等返回 unknown/null/原因。绑定地址范围不是安全诊断结论。没有调用真实模型解释指标。

`GET /api/v1/system/diagnostics` 与 `POST /api/v1/system/diagnostics/run` 都执行实际健康检查。返回 `kind: runtime_health_checks`、检查时间、各检查状态/耗时和实测通过数；SQLite 检查执行当前存储读取，sidecar 通过已有 dependency_checks 访问配置中的实际地址。没有预设 113 项，也没有执行模型质量评测或项目回归套件。
